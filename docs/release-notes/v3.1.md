# libYSE 3.1 — release notes

Body of the v3.1.0 GitHub release (everything below the rule).

---

libYSE 3.1 is a minor release on top of 3.0.1. It adds device enumeration
without opening a stream, makes autoReconnect return to the device you opened
and report what it did, and fixes an out-of-bounds write in the desktop audio
callback. The C API only gains functions; no existing function changes its
signature.

## Behaviour changes

- **Band-pass filters pass their centre frequency at unity gain.** The old
  normalisation boosted the centre by about 1.77x at Q 1 and up to 2x
  (+6 dB) at low Q. `bandPass`, the `bandPassFilter` module and the patcher's
  `~bp` are now up to 6 dB quieter at the centre frequency. Re-check levels in
  patches and mixes that rely on a band-pass (#1022).
- **autoReconnect reopens the device you opened**, not the system default.
  Before, a host that had opened an external interface was moved to the
  built-in output after a dropout without being told. `resume()` follows the
  same path (#1027).

## New

- **`System().refreshDevices()` / `yse_system_refresh_devices()`** lists audio
  devices without opening a stream: before `init()`, on an `initOffline()`
  session, and while a device plays. With no stream open it restarts the
  backend so hot-plugged devices appear. It also lets `openDevice()` work on
  an offline session. A refresh replaces the device list: look devices up
  again by name and host afterwards (#1026).
- **Reconnect policy and outcome.** `autoReconnect(on, delay,
  fallbackToDefault, maxAttempts)` adds an opt-in fallback to the default
  device and a limit on failed attempts in a row. `reconnectState()`
  (`RS_NONE`, `RS_RECONNECTING`, `RS_RESTORED`, `RS_FELL_BACK_TO_DEFAULT`,
  `RS_FAILED`),
  `reconnectCount()`, `getActiveDevice()` and `getActiveHost()` say what
  happened and which device is playing. The two-argument `autoReconnect`
  behaves as before apart from the reconnect target (#1027).
- **C API:** `yse_system_refresh_devices`, `yse_system_auto_reconnect_config`,
  `yse_system_get_reconnect_state`, `yse_system_get_reconnect_count`,
  `yse_system_active_device`, `yse_system_active_host`, and the
  `YseReconnectState` enum.

## Fixes

- **Out-of-bounds write on the audio thread.** When the speaker layout had
  more outputs than the open stream (for example after `openDevice()` to a
  device with fewer channels, or `init()` on a mono default device), the
  PortAudio callback wrote past the end of the stream's buffer. It now copies
  only the channels both have and writes silence to the rest. The layout is
  narrowed to fit the stream when it opens. The Android backend's matching
  out-of-range read is fixed the same way (#1028).
- The PortAudio callback writes silence when no sound is playing, instead of
  leaving the output buffer untouched (#1029).
- If a stream opens but fails to start, `openDevice()` closes it instead of
  leaving it half-open (#1027).

## Known limitation

On PortAudio, a device that was unplugged and plugged back in may not be found
by the reconnect watchdog until the host calls `refreshDevices()`. A host can
do that while `reconnectState()` reads `RS_RECONNECTING`.

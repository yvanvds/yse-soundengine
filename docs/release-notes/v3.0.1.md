# libYSE 3.0.1 — release notes

Body of the v3.0.1 GitHub release (everything below the rule).

---

libYSE 3.0.1 is a patch release. It rewrites the patcher object reference and
fixes six patcher bugs that the rewrite turned up. There are no API or ABI
changes.

## Behaviour changes

Both of these fix buggy defaults, but a patch that relied on the old
behaviour will sound different:

- **`~+` and `~-` default their right operand to 0** (was 1). A bare `~+` used
  to add a full-scale DC offset to its signal. If a patch relied on that
  offset, give the object the argument `1` (#1015).
- **`~bp` defaults to Q 1** (was 0). At Q 0 the filter was bypassed and its
  input passed through at double level. A `~bp` that sets its Q is not
  affected (#1020).

## Fixes

- `.programchange` and `.channelpressure` no longer send an extra zero byte,
  and the older MIDI senders clamp the channel to 0–15 instead of corrupting
  the status byte (#1014).
- `~+`, `~-`, `~*`, `~/` and `~clip` accept ints on their control inlets.
  Before, ints were silently ignored (#1016).
- `.ftom` and `.mtof` always send a finite value. A frequency of 0 or below
  used to give `-inf` or NaN. The scalar `DSP::FreqToMidi` /
  `DSP::MidiToFreq` helpers now clamp like their buffer versions (#1017).
- `~line`'s `stop` holds the ramp until a new target arrives. It used to
  resume after one block (#1019).

## Documentation

- The [patcher object reference](https://yvanvds.github.io/yse-soundengine/patcher/objects/index.html)
  has been rewritten. Each object starts with a short summary, followed by
  notes in paragraphs and lists. Objects are described in YSE's own terms,
  and about 30 places where the old text didn't match the code are fixed
  (#997, #998).
- `yse_patcher_get_type_description()` now returns that short summary
  (300 characters at most) instead of a long paragraph, so an editor can show
  it as a tooltip.
